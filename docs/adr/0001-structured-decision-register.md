### 3.1 Design
- [user] 8 scenarios x 2 arms (register vs plain grill-me): fixtures f2, f3, f4; real replays cf0e6748 and 4fad5622 (turns 1-19); three scenarios built from stress-test logs (queue-field backfill with a falsified premise; reflect-gate hook plan; model-pin policy dotfiles#375).

- [user, by "go with your recommendation"] 5 repeats per cell first, then up to 15 per cell (the user's batches of 5 are reduced to looks at 5 and 15 [assistant], see 3.3). Closed-form credible intervals, no Stan.
- Follow-on: weeks of real use [assistant].

### 3.2 Outcome measure
- [verified] The f4 study scored blinded item classification; headline = REAL_LOSS count (an unrecovered decision or mistake), with a range where UNCLEAR items exist (notes/seq-study-closeout-20261114.md). Its pre-registered bands: 2 or fewer = helps; 3 = ambiguous; about 4 or more = not enough (notes/seq-study-arm-ap-build-20261114.md).
- [assistant] Here: per run, real losses against the scenario key, blinded classification as in f4. Per scenario s, d_s = mean(register) - mean(plain). Secondary: cost per run, enforcement events.

### 3.3 Stopping rule and verdicts [assistant proposal]
Let D = the unweighted mean of d_s over the k <= 8 scenarios that stay valid (scenarios with different item counts are pooled unweighted [assistant]), with a Student-t interval on k-1 degrees of freedom (7 for k=8) from the per-scenario d_s. Not a flat-prior normal interval: with unknown variance it is too narrow.
- Looks after 5 and after 15 runs per cell (no look at 10). Stop at the first look where a verdict below is reached; at 15 per cell stop regardless.
- **Go**: the upper bound of the interval for D is <= -0.5 (register loses fewer; the lower end of the reduction is >= 0.5 real losses per run), AND cost per run is no more than 2x control. An early Go at 5 per cell requires the 95% t interval to satisfy this; the final look at 15 uses 90%.
- **No-go**: lower bound of the interval for D above 0 (register loses more; 95% at the look of 5, 90% at 15), OR the interval lies within +/-0.5 at 15 per cell (no useful effect), OR cost exceeds 2x control with no Go on losses.
- **Inconclusive**: anything else at 15 per cell. The user then decides by judgement; no tie-break is pre-set.
- Interval width is bounded below by the between-scenario SD / sqrt(k), so more repeats per cell narrow only within-scenario noise; Inconclusive is a likely outcome.
- Intent-to-treat: every run that completed is scored, including register-arm runs with zero register calls. A run is void ONLY on an infrastructure fault (3.4), by the same rule in both arms; void runs are reported, not scored.
- Thresholds (0.5, 2x, 90%, 95%, looks at 5 and 15) are declared [assistant] constants, not measured; the earlier 5/10/15 look cadence was inferred from the user's "go with your recommendation".
- The control arm is open: section 9, OQ1.

### 3.4 Checks
- Manipulation check is now a reported metric, not a void rule: enforcement events (rejections, hook blocks, caps hit, fail-opens) are logged per run, with open_branch_calls and main-line entries before/after. Engagement (share of register-arm runs with >=1 register call; calls per run) is a secondary result.
- Hook heartbeat/event log (2.8 R4): a run is void only if hooks did not fire when they should have, or on truncation, auth/OAuth error, or cost-cap truncation (infrastructure faults, both arms alike).
- Step 0 (before any scored run), live checks under `claude -p`: (a) hooks fire; (b) scoping: a hook does not fire before the skill is invoked / without the activation marker; (c) which session identifier the MCP server and hooks each see. First check about USD 0.07 [estimate: notes/seq-study-pilot-results-20261114.md:92 proposes it; not yet run, not an observation]. If no scoping mechanism works the verdict is RESTRUCTURE (Q1 revisited with the user).
- Pass the prompt on stdin when `--allowedTools` or `--tools` precedes it.
